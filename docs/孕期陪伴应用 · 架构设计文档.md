# 孕期陪伴应用 · 架构设计文档

版本 v0.1 · 2026-11-16 · 自用项目 · 状态：草稿

## 1. 背景与目标

这是一个陪伴孕期直至宝宝出生的个人工具：由我一人录入，家人只读查看，并把关键日程单向推送到手机系统日历（HarmonyOS）。

目标：

- 完整、可追溯地记录每次产检及结果（含报告、B超原图）
- 低成本记录每日饮食、症状、补剂和特殊事项
- 产检预约、关键节点、预产期自动出现在系统日历并带提醒
- 家人通过只读链接或日历查看，无需注册账号
- 数据自有：自部署、可备份、可导出

## 2. 范围

**MVP 范围内**：孕周计算、产检管理、指标与趋势、附件存档、每日记录、补剂提醒、备注与问题清单、关键节点规则、日历 ICS 输出、只读分享页。

**后续阶段**：胎动计数、宫缩计时、待产清单、产后宝宝记录（喂养/睡眠/疫苗/生长曲线）、报告 OCR、CalDAV 推送。

**非目标**：多用户注册与 SaaS 化、医学诊断或风险判断、内容推送与社区、双向日历同步、电商。

## 3. 用户与角色

| 角色 | 说明 | 权限 |
| --- | --- | --- |
| 记录者 | 唯一账号持有者（我） | 全部读写 |
| 查看者 | 家人，通过分享令牌访问 | 只读，且只能看到标记为可见的内容 |
| 日历客户端 | 手机系统日历订阅 | 只读 ICS 订阅 |

## 4. 功能需求

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| F1 | 孕周引擎 | 以预产期为基准计算孕周+天、倒计时；支持B超校正并保留历史 |
| F2 | 产检管理 | 日期、医院、医生、医嘱、下次预约、小结；一次产检可挂多项指标和附件 |
| F3 | 指标与趋势 | 体重、血压、宫高、腹围、胎心、血尿检、B超径线等；按孕周画趋势 |
| F4 | 附件存档 | 报告/B超图拍照上传，按产检或日期归档 |
| F5 | 每日记录 | 饮食（照片+一句话）、症状标签、情绪、备注，强调快速录入 |
| F6 | 补剂 | 补剂计划、每日打卡、提醒 |
| F7 | 备注与问题清单 | 带标签的特殊事项；下次要问医生的问题及状态 |
| F8 | 关键节点规则 | 可配置的产检参考窗口（以医院实际安排为准），随预产期自动推算 |
| F9 | 日历输出 | 产检、节点、预产期、补剂提醒生成 ICS 订阅 |
| F10 | 只读分享页 | 孕周概览、最近产检、趋势、可见记录；令牌访问 |

## 5. 非功能需求

- **隐私第一**：属于健康数据，自部署，传输加密，最小暴露面
- **易录入**：移动端优先，常用值预填，大按钮；弱网可暂存后同步
- **数据安全**：每日自动备份，可演练恢复
- **规模很小**：单用户，数据量以 GB 计即可，无需高可用与分布式
- **可维护**：依赖少，单机 Docker Compose 部署，配置化而非硬编码规则
- **非医疗产品**：只展示与提醒，不做诊断；异常值仅按报告给出的参考范围轻量标注

## 6. 总体架构

```
 手机浏览器(PWA, 录入)    家人手机(只读页)    手机系统日历(订阅)
         |  HTTPS               |  HTTPS            |  HTTPS (ICS)
         v                      v                   v
  +------------------- 反向代理 (TLS) --------------------+
  |                                                       |
  |  Web/API 服务                                         |
  |   - 认证 / 分享令牌                                   |
  |   - 孕周引擎  - 产检/指标  - 日常记录  - 备注/问题    |
  |   - 日历生成器 (业务数据 -> 事件 -> ICS)              |
  |        |                          |                   |
  |   数据库 (SQLite 或 PostgreSQL)   附件存储 (本地目录) |
  +-------------------------------------------------------+
        定时任务：备份、里程碑重算
```

要点：应用是唯一数据源；日历与只读页都是它的派生视图。

| 层 | 建议 | 备注 |

## 8. 数据模型

### 8.1 设计原则

- 日期用 DATE，时间戳用 UTC；时区由配置项决定
- 孕周以「孕天数」（gestational\_days）存储，展示时转为「周+天」
- 指标采用窄表，便于按指标跨产检画趋势
- 主要业务表带 version、updated\_at、deleted\_at（软删除）
- 可见性：需要对查看者控制的表带 viewer\_visible

### 8.2 表结构（SQLite/PostgreSQL 通用写法，已简化）

```sql
CREATE TABLE pregnancy (
  id INTEGER PRIMARY KEY,
  edd_date DATE NOT NULL,          -- 当前采用的预产期
  edd_source TEXT NOT NULL,        -- lmp | ultrasound | manual
  lmp_date DATE,                   -- 可选
  created_at TIMESTAMP NOT NULL
);
CREATE TABLE edd_history (
  id INTEGER PRIMARY KEY, pregnancy_id INT NOT NULL,
  edd_date DATE NOT NULL, source TEXT NOT NULL,
  note TEXT, changed_at TIMESTAMP NOT NULL
);

CREATE TABLE checkup (
  id INTEGER PRIMARY KEY, pregnancy_id INT NOT NULL,
  visit_date DATE NOT NULL, visit_time TIME,
  hospital TEXT, doctor TEXT,
  summary TEXT, advice TEXT,
  next_visit_date DATE, next_visit_time TIME,
  viewer_visible BOOLEAN NOT NULL DEFAULT TRUE,
  viewer_note TEXT,                -- 写给查看者的说明
  version INT NOT NULL DEFAULT 1,
  created_at TIMESTAMP NOT NULL, updated_at TIMESTAMP NOT NULL,
  deleted_at TIMESTAMP
);

CREATE TABLE metric_def (
  code TEXT PRIMARY KEY, name TEXT NOT NULL, unit TEXT,
  category TEXT NOT NULL,          -- vital | lab | ultrasound
  value_type TEXT NOT NULL,        -- num | text
  ref_low REAL, ref_high REAL      -- 取自报告，仅供轻量标注
);
CREATE TABLE metric_value (
  id INTEGER PRIMARY KEY, code TEXT NOT NULL REFERENCES metric_def(code),
  checkup_id INT, daily_log_id INT,   -- 至少关联其一，或独立测量
  measured_at TIMESTAMP NOT NULL, ga_days INT,
  value_num REAL, value_text TEXT
);

CREATE TABLE daily_log (
  id INTEGER PRIMARY KEY, log_date DATE NOT NULL UNIQUE,
  mood TEXT, note TEXT,
  viewer_visible BOOLEAN NOT NULL DEFAULT TRUE,
  updated_at TIMESTAMP NOT NULL
);
CREATE TABLE meal_entry (
  id INTEGER PRIMARY KEY, daily_log_id INT NOT NULL,
  meal_type TEXT NOT NULL,         -- breakfast|lunch|dinner|snack
  description TEXT, attachment_id INT
);
CREATE TABLE symptom_entry (
  id INTEGER PRIMARY KEY, daily_log_id INT NOT NULL,
  tag TEXT NOT NULL, severity INT, note TEXT
);

CREATE TABLE supplement_plan (
  id INTEGER PRIMARY KEY, name TEXT NOT NULL, dosage TEXT,
  start_date DATE NOT NULL, end_date DATE,
  remind_time TIME, rrule TEXT,    -- 如 FREQ=DAILY
  active BOOLEAN NOT NULL DEFAULT TRUE
);
CREATE TABLE supplement_check (
  id INTEGER PRIMARY KEY, plan_id INT NOT NULL,
  check_date DATE NOT NULL, taken BOOLEAN NOT NULL,
  UNIQUE (plan_id, check_date)
);

CREATE TABLE question (
  id INTEGER PRIMARY KEY, text TEXT NOT NULL,
  status TEXT NOT NULL,            -- open | asked | answered
  checkup_id INT, answer TEXT,
  created_at TIMESTAMP NOT NULL, answered_at TIMESTAMP
);
CREATE TABLE note (
  id INTEGER PRIMARY KEY, occurred_at TIMESTAMP NOT NULL,
  title TEXT, body TEXT, tags TEXT,   -- tags 存 JSON 数组
  viewer_visible BOOLEAN NOT NULL DEFAULT FALSE,
  created_at TIMESTAMP NOT NULL, updated_at TIMESTAMP NOT NULL
);

CREATE TABLE attachment (
  id INTEGER PRIMARY KEY,
  owner_type TEXT NOT NULL, owner_id INT NOT NULL,
  kind TEXT NOT NULL,              -- report|ultrasound|photo|other
  filename TEXT, mime TEXT, size_bytes INT,
  sha256 TEXT, storage_path TEXT NOT NULL,
  created_at TIMESTAMP NOT NULL
);

CREATE TABLE milestone_rule (
  id INTEGER PRIMARY KEY, code TEXT NOT NULL UNIQUE, title TEXT NOT NULL,
  start_ga_days INT NOT NULL, end_ga_days INT NOT NULL,
  enabled BOOLEAN NOT NULL DEFAULT TRUE, note TEXT
);

CREATE TABLE share_token (
  id INTEGER PRIMARY KEY, token_hash TEXT NOT NULL UNIQUE,
  scope TEXT NOT NULL,             -- view | calendar
  label TEXT, created_at TIMESTAMP NOT NULL,
  expires_at TIMESTAMP, revoked_at TIMESTAMP
);
```

索引建议：metric\_value(code, measured\_at)、checkup(visit\_date)、attachment(owner\_type, owner\_id)。

## 9. 核心流程

### 9.1 孕周计算

- 孕天数 = 280 − (预产期 − 目标日期) 的天数
- 孕周 = 孕天数 ÷ 7（整数部分）+ 孕天数 mod 7（天）
- 预产期被B超校正时，写入 edd\_history，并重算里程碑窗口；历史记录中已存储的 ga\_days 保持不变

### 9.2 产检录入

1. 新建产检（日期、医院、医生），孕周自动带出
2. 录入指标：常用指标预填上次单位，输入即写入 metric\_value
3. 拍照上传报告/B超，写入 attachment 并关联产检
4. 填写医嘱、下次预约；可选写一句 viewer\_note 给查看者
5. 保存后，日历输出自动反映新的下次预约

### 9.3 里程碑窗口

- 里程碑规则存于 milestone\_rule，仅为**默认参考**，可随时修改或停用，实际以医院安排为准
- 默认可预置的参考项：建档、NT、唐筛/无创、大排畸、糖耐量、B族链球菌筛查、胎心监护等，具体孕周区间由你按医院通知核对后填入
- 窗口日期 = 预产期 − 280 天 + 规则孕天数，按预产期实时计算，不单独存储

### 9.4 查看者过滤

只读页和 ICS 只输出 viewer\_visible = TRUE 且未删除的内容；展示时优先显示 viewer\_note，原始医嘱默认不展示。

## 10. 日历同步模块

### 10.1 原则

- **单向**：应用 → 日历，日历中的修改不会回写
- **事件是派生视图**：由业务数据即时计算，不单独维护事件表
- **幂等**：同一份数据生成的 ICS 内容稳定，便于客户端比对

### 10.2 事件映射

| 来源 | 事件 | 提醒 |
| --- | --- | --- |
| checkup.next\_visit\_\* | 产检（有时间则定时，否则全天） | 前一天、当天前2小时 |
| pregnancy.edd\_date | 预产期（全天） | 前一周 |
| milestone\_rule + 预产期 | 产检窗口（跨天全天事件） | 窗口开始当天 |
| supplement\_plan | 补剂（RRULE 重复） | 每天 remind\_time |

标题保持通用（如「产检」「补剂」），指标、医嘱、症状一律不进日历。可提供隐私开关，使标题进一步泛化。

### 10.3 标识与更新

- UID 稳定，形如 类型-记录ID@你的域名，例如 checkup-42@preg.local
- SEQUENCE 取来源记录的 version；LAST-MODIFIED 取 updated\_at
- 记录取消或被软删除后，事件直接从输出中消失

### 10.4 ICS 示例

```
BEGIN:VCALENDAR
VERSION:2.0
PRODID:-//preg-companion//CN
CALSCALE:GREGORIAN
X-WR-CALNAME:孕期日程
BEGIN:VEVENT
UID:checkup-42@preg.local
DTSTAMP:20261116T080000Z
LAST-MODIFIED:20261116T080000Z
SEQUENCE:2
DTSTART;TZID=Asia/Shanghai:20261201T093000
DTEND;TZID=Asia/Shanghai:20261201T103000
SUMMARY:产检
BEGIN:VALARM
ACTION:DISPLAY
TRIGGER:-P1D
DESCRIPTION:明天产检
END:VALARM
BEGIN:VALARM
ACTION:DISPLAY
TRIGGER:-PT2H
DESCRIPTION:2小时后产检
END:VALARM
END:VEVENT
END:VCALENDAR
```

时区示例为 Asia/Shanghai，实际由配置决定；带 TZID 的事件需附带 VTIMEZONE，由 ICS 库负责生成。全天事件使用 VALUE=DATE，DTEND 为结束日的次日（不含）。

### 10.5 输出方式与演进

| 阶段 | 方式 | 特点 |
| --- | --- | --- |
| 第一阶段 | ICS 订阅链接：GET /cal/{token}.ics，应用按请求实时生成 | 实现最简单，也可分享给家人订阅；刷新频率由手机系统决定，可能有延迟 |
| 第二阶段（按需） | 只读 CalDAV（如 Radicale）：应用把同一份 ICS 写入集合 | 同步更及时，多一个组件；按 UID 比对内容哈希，只 PUT 变化项、DELETE 消失项 |

两阶段共用同一个事件生成器，切换输出方式不影响业务代码。

### 10.6 注意事项

- HarmonyOS 日历对订阅/CalDAV 账号的支持和刷新行为随系统版本而异，**需在实机验证**后决定是否进入第二阶段
- 手机访问订阅地址需要可达的 HTTPS 地址；若服务仅在内网/VPN 内，手机离开内网后将无法刷新
- 响应头设置 Content-Type: text/calendar; charset=utf-8，并支持 ETag/条件请求
- 令牌放在 URL 中，需保证不记入访问日志，并可随时吊销重发

## 12. 安全与隐私

- 全程 HTTPS；记录者使用强口令（argon2/bcrypt 存储），登录限速，可选 TOTP
- 分享令牌：32 字节随机、仅存哈希、按 scope 区分（view / calendar）、可设过期、可吊销
- 附件存放在 Web 根目录之外，通过带鉴权的路由或短时签名链接访问；上传时可去除 EXIF
- 日志不记录令牌、指标值与备注内容
- 静态数据保护：磁盘加密或至少严格的文件权限；数据库与附件目录仅应用账号可读
- 日历内容最小化（见 10.2），避免锁屏、桌面小组件和云同步泄露细节
- 备份加密（如 age/gpg），异地存放一份

## 13. 部署、备份与运维

- **部署**：Docker Compose：app、反向代理（自动 TLS）、可选 Radicale；SQLite 文件与附件目录挂载为数据卷
- **暴露面**：只暴露 /cal 与 /view 所需路径给公网即可；录入端可限制来源或加额外校验
- **备份**：每日 SQLite 在线备份（或 pg\_dump）+ 附件增量同步；保留 30 天；每季度演练一次恢复
- **监控**：健康检查与备份成功告警即可，无需复杂可观测体系
- **导出**：支持按时间范围导出 PDF/JSON，便于带给医生或迁移

## 15. 风险与待定事项

| 事项 | 说明 | 处理 |
| --- | --- | --- |
| 手机日历订阅行为 | 刷新延迟、提醒是否生效取决于系统版本 | M2 实机验证，必要时切换 CalDAV |
| 公网暴露 | 日历订阅需要可达地址 | 令牌+HTTPS+最小输出，必要时仅暴露 /cal |
| 里程碑规则准确性 | 默认窗口只是参考 | 以医院通知为准，规则可配置，文档与界面均注明 |
| 单点故障与数据丢失 | 自部署无云端冗余 | 自动备份+异地副本+恢复演练 |
| 录入负担 | 过重会导致放弃记录 | 优先快速录入路径；先做产检，再做日常 |
| 待定 | 后端语言与前端框架；是否启用 TOTP；医院名称、医生等是否做成可选项 | 实现前确认 |

## 16. 项目目录结构

以下为与语言无关的目录方案，选定后端语言和前端框架后，按其惯例调整目录与文件命名即可。

### 16.1 设计原则

- **分层单向依赖**：api（HTTP 层）→ domain（业务逻辑）→ db（持久化），下层不反向引用上层
- **日历生成器独立成目录**：只读取业务数据，不写库；输出方式（ICS / CalDAV）可替换，不影响业务代码
- **只读页独立入口**：体积小，且不包含任何写操作代码，从构建层面保证查看者无法修改
- **运行时数据与代码分离**：数据库、附件、备份放在单独的数据目录，不入版本库，部署时作为数据卷挂载
- **配置走环境变量**：仓库只提供 .env.example，口令与密钥不入库
- **种子数据版本化**：指标字典、里程碑默认规则放在 seed 目录，随迁移一起管理

### 16.3 关键约定

| 约定 | 说明 |
| --- | --- |
| 附件命名 | 磁盘上用内容哈希命名，相同文件自动去重，也避免原始文件名泄露信息；原始文件名存数据库 attachment.filename，storage\_path 存相对路径 |
| 数据目录权限 | 仅应用运行账号可读写；备份目录单独授权 |
| 依赖方向 | api 可调用 domain 与 calendar；calendar 只读取 domain 提供的查询接口；任何层都不直接拼接其他层的 SQL |
| 只读页构建 | viewer 目录单独打包，不引入录入端的组件与接口客户端 |
| 迁移与种子 | 每次改动表结构新增一个迁移文件；默认指标与里程碑规则用 seed 幂等写入，已被修改的规则不被覆盖 |
| 测试重点 | 孕周计算（含预产期校正）、日历事件生成（ICS 快照比对）、查看者可见性过滤，这三处出错代价最高 |
| 配置项 | 在 .env.example 列全：对外域名、时区、数据目录、令牌默认有效期、备份保留天数 |
